01

Context Engineering & Model Context Protocol

Le fondamenta architetturali di un agente che funziona davvero

Un cambio di paradigma

Dal Prompt Engineering al Context Engineering

Prompt Engineering

Ottimizzare la singola istruzione testuale rivolta al modello. L'unità di lavoro è la stringa.

Context Engineering

Progettare dati, strumenti, vincoli e flussi conversazionali come un sistema coerente. L'unità di lavoro è l'architettura.

Un modello allo stato dell'arte, con un contesto lacunoso, produce inevitabilmente risultati inesatti.
Lo standard

Model Context Protocol (MCP)

Il problema

Integrazioni punto-a-punto: un connettore ad hoc per ogni sistema. Fragili, costose, non scalano — e saturano la finestra di contesto con documentazione irrilevante.

La risposta

MCP crea un livello di astrazione standard tra agenti AI e fonti di dati, in lettura e in scrittura.

Come l'USB-C standardizza la connessione fisica tra dispositivi, MCP standardizza la connessione logica tra un modello e qualsiasi fonte dati.

Architettura

Host → Client → Server

Host

L'applicazione che incorpora il modello, orchestra il flusso e interpreta gli intenti dell'utente.

Client

Middleware integrato nell'Host: gestisce una singola connessione standardizzata con un server MCP.

Server

Applicazione leggera e isolata che espone dati o funzionalità — modulare e riutilizzabile su Host diversi.

Il modello ragiona. L'host esegue. — separation of concerns come principio di sicurezza.
Il contratto

OpenAPI Specification (Swagger)

  • Descrizione machine-readable di un'API REST, in JSON o YAML.
  • Endpoint, metodi HTTP, parametri di input, schemi di risposta — in un unico file.
  • Permette a un server MCP di incapsulare sistemi REST aziendali preesistenti come Tool per l'agente.
  • Condivide con i parametri dei Tool MCP lo stesso linguaggio di schema: JSON Schema.
02

Retrieval-Augmented Generation

Quando il contesto non è un dato, ma testo non strutturato

Il meccanismo

Come funziona la RAG

  • Disaccoppia la conoscenza (un database esterno) dalle capacità di ragionamento del modello.
  • Gli embedding mappano il significato del testo in uno spazio vettoriale.
  • I frammenti più pertinenti vengono recuperati e iniettati nel contesto al momento della query.
A differenza del fine-tuning, il modello resta inalterato: la conoscenza si inietta a ogni singola interrogazione.
Il criterio

Quando conviene usare la RAG — tre condizioni congiunte

Capienza

Il corpus eccede la finestra di contesto del modello.

Località

La risposta è concentrata in pochi frammenti, non aggregata su migliaia di documenti.

Natura semantica

La pertinenza è di significato — non un dato strutturato, temporale o quantitativo.

Dato esatto → API diretta · Azione → Tool · Sintesi globale → aggregazione, non RAG pura.

Due regimi di conoscenza

RAG e Tool/MCP: complementari, non alternativi

RAG

Conoscenza statica vettorializzata. L'agente legge testo non strutturato per similarità semantica.

MCP / Tool

Accesso in tempo reale ai sistemi sorgente. L'agente legge e scrive dati vivi.

Non sono mutuamente esclusivi: un retriever RAG può a sua volta essere esposto come Tool MCP.

I casi Lenovo e Plenitude, tra poco, ne sono la prova empirica.

Caso 1 — SEO

Younited — Pipeline SEO «all-prompt»

1→5
Brand → SEO → Brief → Link → Generazione
cinque fasi sequenziali, contesto iniettato staticamente nel prompt

Nessun tool, nessuna RAG: tutta l'intelligenza è nella catena di prompt e nei delimitatori.

−25/30% tempo di produzione
Query Fan-Out a scala industriale
Conformità E-E-A-T / YMYL
Caso 2 — Rete vendita

Lenovo — Assistente RAG multi-agente

Architettura

Mother Agent qualifica il bisogno → instrada a 4 sub-agenti per fascia di prezzo (Essential, SMB, ThinkPad Classic, Workstation).

Pipeline dati

Excel cleaning → Markdown (Reducto) → Knowledge Base vettoriale indigo.ai.

Gli SKU venivano allucinati: il chunking spezzava la scheda prodotto. Soluzione → chunking guidato dalla struttura Markdown, codice e prezzo nello stesso vettore.
~80% automation rate
Caso 3 — Voicebot

Plenitude «Luce» — Function Calling in tempo reale

  • Nessuna KB statica: backend Swagger interrogato live — POST /lookup, POST /api/lettura.
  • L'agente legge e scrive: da «consiglia» a «opera».
  • Stack vocale: STT → LLM (indigo.ai, GPT-4.1) → TTS (ElevenLabs).
  • Regole di business: disambiguazione multi-fornitura, filtro contatori teleletti.
~85% automation rate

Conclusioni

Maturità tecnica e divario di adozione
